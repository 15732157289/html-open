把一个产品页做进一个 HTML 文件

以 qyhhhh.github.io/BleRemoteBrideg 为蓝本，完整拆解一个「单文件、零框架、免费托管、带交互演示」的产品落地页是怎么做出来的，并给你一套可直接套用的步骤与代码。

托管：GitHub Pages 技术：原生 HTML/CSS/JS 形态：单文件 成本：¥0
qyhhhh.github.io/BleRemoteBrideg/

这份教程分三部分：① 网站解剖——看它到底用了什么技术、怎么组织；② 复刻教程——从零到发布的一步步实操；③ 最佳实践——让页面更快、更稳、更好用的清单。

Part 1 · 网站解剖

这个网站到底是怎么做出来的

先看结论：它不是一个「用框架搭出来的大项目」，而是一个精心编排的单文件落地页。整站就是一个 index.html，约 40KB，纯原生 HTML / CSS / JavaScript，没有任何构建工具，托管在免费的 GitHub Pages 上。这种形态特别适合「开源硬件 / 工具 / 产品」的推广页：打开即用、零依赖、免费、易修改。

1.1 一句话定位

这是一个产品落地页（landing page），唯一任务是：让访问者在 30 秒内看懂「这个 ESP32 固件能干什么、为什么值得用、怎么用」，并引导他去「连接设备 / 看怎么用」。

1.2 技术栈总览

表 1 · 站点技术栈与选择理由

1.3 托管与发布链路

整个过程是「写代码 → 推到仓库 → 自动发布」，没有服务器、没有数据库、没有部署命令。对非程序员也友好：更新内容 = 改一个 HTML 文件再 push。

1.4 页面区块地图

整页按「认知漏斗」组织——先让人看懂是什么，再演示怎么用，最后给购买 / 使用的入口。这个结构可以直接套用到你自己的产品页上：

  1. 导航栏（sticky）：吸顶，含 Logo、锚点链接、「连接设备」主按钮。
  2. Hero 首屏：大标题「10 元改造，让蓝牙遥控器控制电脑」+ 一句话副标题 + 三个能力标签 + 两个按钮。一眼看懂价值。
  3. 实时演示区（DEMO）：页面中心亮点——用 CSS 画出一个遥控器，点它，右侧「电脑屏幕」立即响应。用纯前端模拟真实效果。
  4. 场景区（Scenarios）：刷剧 / Vibe Coding / 演示，三个使用场景卡片，回答「我什么时候用得上」。
  5. 设备界面区：放真实固件配置页的截图 + 交互式逐键识别演示，展示「改键」能力。
  6. 卖点区（Built to be simple）：6 个特性点，回答「为什么选它」。
  7. 兼容性表：一张诚实、带状态标注的兼容矩阵，建立信任。
  8. 上手引导（Get Connected）：三步烧录流程 + 真实「连接设备」按钮（Web Serial）。这是转化动作。

1.5 五个关键实现技术

① 设计令牌（CSS 变量）

在 :root 定义 --blue、--ink、--bg 等颜色与间距变量。改一处、全局生效，保证整页配色一致。

② 内联 SVG 图标

图标不用图标库，而是写在 HTML 里的 <svg>，用 stroke:currentColor 让图标自动跟随文字颜色。

③ CSS 手绘产品模型

遥控器、显示器、PCB 板这些「实物」都用纯 CSS 绘制（渐变、圆角、阴影），不依赖图片，体积小、清晰度无限。

④ 原生 JS 交互演示

点遥控器 → 触发键盘事件 → 右侧「屏幕」切换画面 + 弹出按键提示。全部是 addEventListener，无框架。

⑤ Web Serial 硬件集成

页面右上「连接设备」用 ESP Web Tools，通过浏览器 Web Serial API 直接给开发板烧录固件，用户无需安装任何客户端。

⑥ 响应式与无障碍

用 clamp() 流体字号、grid 自适应列数、媒体查询切换移动端导航；带跳转链接、焦点样式、语义化标签。

关键洞察：这类页面的「技术含量」不在用了多少高级框架，而在于内容编排 + 精确的 CSS + 恰到好处的原生交互。这是零依赖方案能同时兼顾「好看」「够用」「免费托管」「易维护」的原因。
Part 2 · 从零复刻教程

一步一步，做一个你自己的单文件落地页

下面是完整实操。你不需要会编程——照着粘贴、改文字即可；想深挖时，每步都解释了「为什么这么做」。教程以「给一个开源工具做产品页」为假设，但步骤对任何产品 / 项目通用。

本部分目录

  2. 建仓库 + 开启 GitHub Pages
  3. 搭 HTML 骨架
  4. 建立设计系统（CSS 变量）
  5. 布局：导航 / Hero / 区块
  6. 视觉积木：图标 / 产品模型 / 响应式

  8. 进阶：Web Serial 与自动构建

1

准备：账号与工具约 5 分钟

你需要一个 GitHub 账号（免费注册），以及一个能改文本的工具。推荐：

  • VS Code（免费）：写代码用，自带终端。
  • 或者最简方案：直接在 GitHub 网页里编辑文件（见第 1 步），完全不用装任何软件。

本教程假定你用「GitHub 网页编辑 + GitHub Pages 源码分支部署」的最简路径——全程不需要本地装 Git。想用本地 Git 也行，步骤等价。

2

建仓库 + 开启 GitHub Pages约 5 分钟

目标网站 qyhhhh.github.io/BleRemoteBrideg/ 的 URL 结构是「用户名.github.io / 仓库名 /」。所以：

  1. 登录 GitHub → 点右上角「+」→ New repository。
  2. 仓库名填你要的项目名（例如 my-project）。保持 Public（免费托管要求公开）。不要勾选任何初始化文件，或勾选加一个 README 也行。
  3. 创建后进入仓库 → Settings → Pages。
  4. 在 Build and deployment 里，Source 选「Deploy from a branch」，Branch 选 master，目录选 / (root)，Save。
结果：现在只要你的 master 分支根目录有一个 index.html，GitHub 就会自动把它发布到 你的用户名.github.io/仓库名/。保存后首次部署约需 1 分钟，之后每次 push 都会自动更新。
提示：关于分支名——仓库默认可能是 main 而非 master。选 Pages 来源分支时以你仓库实际分支名为准即可，两者等价。
3

搭 HTML 骨架核心

在仓库根目录新建 index.html（GitHub 网页里点 Add file → Create new file）。骨架如下——所有样式写进 <style>，所有脚本写进 <script>，这是单文件方案的关键：

index.html — 最小骨架

<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta name="color-scheme" content="light">
  <title>你的产品名 — 一句话副标题</title>
  <meta name="description" content="用一两句话说明这是做什么的，利于搜索展示。">
  <!-- 用 data-URI 内联一个 SVG favicon，省去单独文件 -->
  <link rel="icon" href="data:image/svg+xml,%3Csvg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 32 32'%3E%3Crect width='32' height='32' rx='7' fill='%232f5fc4'/%3E%3C/svg%3E">
  <style>
    /* ===== 全部样式写在这里 ===== */
  </style>
</head>
<body>
  <header>...导航...</header>
  <main>...页面主体...</main>
  <footer>...页脚...</footer>
  <script>
    /* ===== 全部脚本写在这里 ===== */
  </script>
</body>
</html>

四个 meta 都很重要：charset 保证中文不乱码；viewport 让手机端正确缩放；color-scheme 告诉浏览器你的明暗模式；description 影响搜索摘要。

为什么全部内联？目标站约 40KB 全在一个文件里。好处：① 无需处理文件间路径；② 加载只有一次请求；③ 改一处即发布；④ 复制到任何地方都能离线打开。缺点是单文件会变长——用「分段注释」组织即可：<!-- ===== 视图：Hero ===== -->。
4

建立设计系统（CSS 变量）配色统一的关键

目标站在 :root 里定义了一整套命名变量。这套「设计令牌」让全站配色、圆角、字体高度一致，且改一处全局生效：

:root{
  /* 基础 */
  --bg:#f6f7f9;      /* 页面背景 */
  --paper:#ffffff;   /* 卡片 / 区块背景 */
  --ink:#252931;     /* 主文字 */
  --mut:#667487;     /* 次要文字 */
  --line:#dfe5ed;    /* 分隔线 / 边框 */
  /* 品牌强调色 */
  --accent:#1674ed;  /* 主色：按钮、链接、强调 */
  --accent-dark:#0b55b6;
  --soft:#edf5ff;    /* 主色浅底：标签、高亮块 */
  color-scheme:light;
}

选色建议：一个强调色 + 一套中性色（背景 / 文字 / 边框）就够。强调色用于按钮、链接、当前状态；中性色负责绝大部分布局。克制用色反而更显专业。

字体用系统字体栈，不加载任何外部字体文件，打开秒快：

body{font:15px/1.7 -apple-system,BlinkMacSystemFont,"Segoe UI",
  "PingFang SC","Microsoft YaHei","Noto Sans CJK SC",sans-serif;}

这行让 Windows / macOS / 手机都用各自最舒服的系统字体，中文优先（PingFang、微软雅黑、思源黑体），又无需下载字体文件。

5

布局：导航 / Hero / 区块结构

吸顶导航：用 position:sticky 让它贴住顶部，加一点毛玻璃背景。

header{position:sticky;top:0;z-index:25;
  background:#ffffffed;backdrop-filter:blur(14px);
  border-bottom:1px solid var(--line)}
.nav{height:70px;display:flex;align-items:center;
  justify-content:space-between;gap:24px}

Hero 首屏：用 grid 做左右两栏（左侧文案、右侧演示区），标题用 clamp() 实现随屏幕平滑变化的大小，既在手机不溢出、又在宽屏有气势：

.hero{display:grid;grid-template-columns:1fr 1.12fr;
  gap:42px;align-items:center;padding:48px 0 34px}
h1{font-size:clamp(42px,4.2vw,59px);font-weight:800;
  letter-spacing:-2.2px;line-height:1.2}
/* 大标题里给品牌词上色 */
h1 em{font-style:normal;color:var(--accent)}

内容区块：每个章节一个 <section>，内部用「眉标 + 标题 + 说明」的统一头，让整页有清晰节奏。按钮统一用类：

.btn{display:inline-flex;align-items:center;gap:9px;
  min-height:44px;padding:10px 18px;border:1px solid #d5dfeb;
  background:#fff;border-radius:9px;font-weight:600}
.btn-primary{background:var(--accent);color:#fff;border-color:var(--accent)}
.btn-text{background:none;color:var(--accent);border:0;
  text-decoration:underline}
内容编排提醒：别一上来就堆代码。先把你的页面写成「一屏一句」的大纲——首屏说什么、演示什么、三个卖点、一张兼容表、一个行动按钮——把内容定下来，布局只是让内容讲清楚。
6

视觉积木：图标 / 产品模型 / 响应式让它好看

内联 SVG 图标

定义统一的 .icon 类，用描边 + currentColor，图标就能自动跟随文字颜色，想换色就换文字色：

.icon{width:20px;height:20px;fill:none;
  stroke:currentColor;stroke-width:1.7;
  stroke-linecap:round;stroke-linejoin:round}
/* 用法：一行图标 */
<svg class="icon" viewBox="0 0 24 24">
  <path d="M8 10h6v12H8m16-12h-6v12h6M11 16h10"/>
</svg>

CSS 手绘产品模型

目标站的遥控器、显示器、PCB 都是 CSS 画的。核心技巧是渐变 + 圆角 + 内阴影 + clip-path，用来模拟金属质感、按钮立体感。一个「遥控器按钮」示意：

.rb{position:absolute;width:43px;height:43px;border-radius:50%;
  border:1px solid #101010;
  background:linear-gradient(135deg,#414242,#202121); /* 深色立体 */
  box-shadow:inset 0 0 0 1px #ffffff25; /* 内高光 */
  color:#eee;display:grid;place-items:center}
/* 悬停 / 按下时亮成品牌色 */
.rb:hover{filter:brightness(1.18)}
.rb.pressed,.rb:focus-visible{background:#327ede;
  box-shadow:0 0 0 3px #327ede40;color:#fff}
取舍建议：能用 CSS 画、又需要极清晰（比如设备示意图）的，就用 CSS；而真实截图、实拍图、复杂产品照片应放图片文件（如 assets/ 目录），别硬用 CSS 抠。图标、状态点、导航符号用 SVG/CSS；人物、真实产品用真实图片。

响应式

用媒体查询在窄屏切换布局，并隐藏不重要的导航：

@media (max-width:860px){
  .hero{grid-template-columns:1fr}   /* Hero 变单列 */
  .cards{grid-template-columns:1fr}  /* 卡片堆叠 */
  .nav-links{display:none}           /* 导航收进菜单 */
  .menu-toggle{display:flex}
}
7

交互：原生 JS 演示让页面「活」起来

目标站最亮眼的是「点遥控器 → 屏幕响应」的实时演示。它本质是：一个点击事件 + 几段状态切换，不需要任何框架。思路如下：

<!-- 遥控器上的每个键都是一个带 data 的按钮 -->
<button class="rb" data-key="ENTER">OK</button>
<button class="rb" data-key="ARROW_LEFT">←</button>
// 1. 绑定点击：点哪个键
remote.addEventListener('click', e=>{
  const key = e.target.closest('.rb');
  if(!key) return;                    // 点的不是键就忽略
  const action = key.dataset.key;
  flash(key);                          // 键亮一下
  applyAction(action);                 // 让右侧屏幕响应
  showToast(action);                   // 弹出提示条
});

// 2. 让右侧「屏幕」响应（这里只是演示，不发真实按键）
function applyAction(a){
  if(a==='ENTER')      togglePlay();
  if(a==='ARROW_LEFT') prevSlide();
  if(a==='ARROW_RIGHT')nextSlide();
  // ... 按你的产品逻辑映射
}

还可以加「自动演示」：用 setInterval 定时模拟按几个键，直到用户手动点一下才接管（clearInterval）。「重新开始」则重置状态并重新播放。

诚实标注：目标站演示区明确写着「浏览器模拟 · 非设备实时数据」。如果你的演示是模拟而非真实，也建议加一行说明，避免误导用户、减少无谓的 bug 反馈。
8

进阶：Web Serial 与自动构建可选，按需

（可选）用 ESP Web Tools 在浏览器里烧录固件

目标站右上「连接设备」能在浏览器直接给 ESP32 烧固件。它基于 Chrome/Edge 的 Web Serial API，接入方式是一行自定义元素（需引入其脚本）：

<script type="module"
 src="https://unpkg.com/esp-web-tools@9/dist/web/install-button.js"></script>

<esp-web-install-button manifest="./firmware-dist/latest/manifest.json">
  <button slot="activate">连接设备</button>
</esp-web-install-button>

manifest.json 描述了固件文件与版本；配合 ESP32 的 arduino-cli 编译出 .bin 后放进仓库即可。这样用户无需安装任何客户端就能升级固件。

（可选）用 GitHub Actions 自动构建 + 部署

目标仓库有 .github/workflows，作用类似「每次 push 自动编译固件、再触发 Pages 部署」。一个最小工作流：

# .github/workflows/deploy.yml
name: Build & Deploy
on: [push]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      # ……在这里编译你的固件 / 处理产物……
      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./   # 把根目录发布为 Pages 内容

如果你只是做「纯静态落地页」，其实不需要 Actions——直接在 Pages 设置里选 master 分支的根目录就能发布（见第 2 步）。Actions 是为「需要编译固件」才加。

9

发布与验证收尾

  1. 在 GitHub 仓库根目录确认有 index.html（以及需要的 assets/、firmware-dist/ 等）。
  2. 提交（Commit changes）。若你启用了 Pages 源码分支部署，稍等约 1 分钟。
  3. 打开 https://你的用户名.github.io/仓库名/，亲自验证三件事：手机端不溢出、所有按钮都有反馈（没有点了没反应的僵尸按钮）、图片路径正确（不会裂图）。
  4. 用浏览器的「开发者工具 → 移动端模拟」检查窄屏；用「无障碍 / Lighthouse」跑一遍，看性能与可访问性。
验收标准：一个单文件落地页上线 = 首屏能看懂是什么 → 演示区让用户「哦原来这样」→ 兼容表建信任 → 用户点了你的行动按钮。达到这条链路即算成功。
Part 3 · 最佳实践

让页面更稳、更快、更好用

3.1 上线前自检清单

  • 响应式：手机端单列、无横向溢出；卡片列数每档都不出现「最后一行只剩 1 个」。
  • 无僵尸按钮：每个看着能点的元素都有真实动作或「演示中」提示。
  • 图片路径：全部写在 src 或 CSS url() 里，且能在线上打开。
  • 无障碍：有跳转链接、焦点可见、语义化标签、尊重 prefers-reduced-motion。
  • 性能：不加载多余字体/库；能 CSS 画的就不用图片；图片用真实尺寸不硬撑。
  • 诚实标注：演示是模拟还是真实、兼容性是实测还是推断，都写明，别让用户误判。

3.2 常见坑与解法

表 2 · 高频问题
现象原因 / 解法
手机上字太小 / 布局乱漏了 viewport meta；Hero 用了固定像素宽。加 viewport，用 grid+媒体查询堆叠。
中文乱码缺 <meta charset="utf-8">，或文件不是 UTF-8 保存。
图片裂图路径写错 / 用了会过期的临时链接。用相对路径 assets/xx.png，图片必须真实存在于仓库。
按钮点了没反应僵尸按钮：<a href="#"> 无动作、<button> 无监听。要么绑真实行为，要么删掉。
页面半天加载不出来引了没必要的 JS 库或外链字体。单文件方案默认什么都不引，速度最快。
改了文件不生效浏览器缓存旧版。强制刷新（Ctrl+F5）；或确认已 push 到正确分支并等部署完成。
